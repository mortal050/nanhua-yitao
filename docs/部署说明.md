# 部署说明（公网链接怎么拿）

项目已经在本地构建通过、并用 Playwright 按「GitHub Pages 子路径」的方式预检过（零错误、零失败请求），
所以部署后只要等 Pages 生效就能直接访问。

---

## 方案 A：一条命令部署到 GitHub Pages（推荐）

### 1. 生成 Token（只做一次）

1. 打开 <https://github.com/settings/tokens>（若还没登录先登录 GitHub）。
2. 点 **Generate new token** → 选 **classic** → 勾选 **repo** 这一个权限即可 → 生成。
3. 复制形如 `ghp_xxxxxx` 的字符串（页面关掉就再也看不到了）。

### 2. 运行部署

**最简单**：双击项目根目录的 **`一键部署到GitHub.cmd`**，把 Token 粘贴进去回车。

**或者**在 PowerShell 里：

```powershell
cd C:\Users\29590\Documents\deepseek-harness\default-workspace\nanhua-yitao
$env:GITHUB_TOKEN="ghp_你的Token"
node tools/deploy-gh.mjs
```

脚本会自动完成：

1. 用 Token 查账号 → 创建仓库 `nanhua-yitao`（已存在就跳过）
2. 提交并推送**源码**到 `main` 分支
3. 以 `BASE_PATH=/nanhua-yitao/` 构建，把 `dist` 推送到 **`gh-pages`** 分支
4. 调用 GitHub API 打开 **Pages**（Settings → Pages，源为 gh-pages 分支）

### 3. 拿到链接

脚本最后会打印：

```
================ 部署完成 ================
🌐 公网地址： https://<你的用户名>.github.io/nanhua-yitao/
📦 仓库地址： https://github.com/<你的用户名>/nanhua-yitao
（首次发布可能需要 1~2 分钟生效）
```

首次访问若显示 404，等 1～2 分钟刷新即可（Pages 首次构建需要时间）。

也可以用它来检查 Pages 状态并自动轮询公网地址是否就绪：

```powershell
$env:GITHUB_TOKEN="ghp_你的Token"
node --use-system-ca tools/enable-pages.mjs
```

## 本机实测：遇到的 3 个报错与解决办法（脚本已自动处理）

这台机器的网络环境比较特殊（安全软件 / 代理会做 HTTPS 拦截，且证书吊销列表不可达），
第一次执行时踩了 3 个坑，脚本已经内置了自动修复，**换台电脑一般不会遇到**。记录如下：

| 报错 | 原因 | 解决办法（脚本已内置） |
| --- | --- | --- |
| `TypeError: fetch failed`<br>`unable to verify the first certificate`<br>`UNABLE_TO_VERIFY_LEAF_SIGNATURE` | 安全软件/代理做了 TLS 拦截，Node 默认的 CA 列表不认它的证书 | 用系统证书库重跑：`node --use-system-ca tools/deploy-gh.mjs`。脚本会先探测，发现证书错误就**自动带该参数重新执行自己** |
| `schannel: next InitializeSecurityContext failed: CRYPT_E_NO_REVOCATION_CHECK` | Git for Windows 用 schannel 校验证书时连不上吊销列表 | 脚本给每条 git 命令都加了 `-c http.schannelCheckRevoke=false -c http.sslVerify=false`（只作用于脚本内部，不改你的全局 git 配置）。想恢复严格校验就设 `GIT_STRICT_TLS=1` |
| `Error: spawnSync npm.cmd EINVAL` | Node 20+ 出于安全考虑不再允许直接 spawn `.cmd` | 脚本改为直接用 `node node_modules/vite/bin/vite.js build` 构建，不再依赖 npm |

另外：**首次开启 Pages 时 GitHub 接口偶尔会返回 500**，脚本会自动重试 4 次；
仍失败就到仓库 **Settings → Pages** 手动把 Source 选成 `gh-pages` 分支即可。

## 方案 B：手动部署（不用脚本）

```bash
cd nanhua-yitao
npm install
BASE_PATH=/nanhua-yitao/ npm run build       # Windows PowerShell: $env:BASE_PATH="/nanhua-yitao/"; npm run build
```

把 `dist/` 里的**全部文件**上传到仓库的 `gh-pages` 分支，然后在
**Settings → Pages** 选择 `Deploy from a branch` → `gh-pages` → `/ (root)` → Save。

> 关键点：**必须用 `BASE_PATH=/仓库名/` 构建**，否则子路径下静态资源会 404（项目用 Hash 路由，所以刷新不会 404）。

---

## 方案 C：备选 Netlify（不需要 GitHub）

1. 先构建：`npm install && npm run build`（Netlify 部署在根路径，**不用**设 `BASE_PATH`）。
2. 把 `dist` 文件夹**压缩成 zip**（或直接拖文件夹）。
3. 打开 <https://app.netlify.com/drop>，把 zip 拖进去。
4. 几秒后就会得到一个形如 `https://xxxx-yyyy.netlify.app` 的公网地址。
