# 南华易淘 · 上台讲解提纲

> 目标：3～5 分钟把「网站做了什么 → 代码怎么组织 → 知识点落在哪 → 为什么这么写」讲清楚。
> 讲解顺序建议：**演示 4 个页面 → 讲 3 个技术亮点 → 回答提问**。

## 一、开场（20 秒，照着说）

> 我做的是一个纯前端的**校园二手交易平台「南华易淘」**，主题是让闲置在校园里流动起来。
> 技术栈是 **Vue 3 + Vite + Vue Router + Pinia**，没有后端，数据存在浏览器 localStorage 里。
> 整个项目共 **8 个页面、43 个单文件组件**，还专门做了一个「Vue 知识实验室」页面，用 10 个可交互的小演示
> 覆盖了 Vue 官方教程的全部章节。网站已经部署到了 GitHub Pages，可以公网访问。

## 二、现场演示动线（约 2 分钟，按顺序点）

| 步骤 | 操作 | 要说明的点 |
| --- | --- | --- |
| 1 | 首页 | 数据看板的数字来自 Pinia 的 computed 统计；点「展开平台动态」是**异步组件 + Suspense** |

| 10 | 地址栏随便打个乱路径 | 404 页面（通配路由 `/:pathMatch(.*)*`） |

## 三、代码结构（30 秒讲完）

```
src/
├─ main.js        createApp + 插件 + 全局指令 + 全局组件      ← 应用如何启动
├─ App.vue        布局 + <RouterView> + 路由过渡
├─ router/        8 条路由：懒加载、动态参数、守卫
├─ stores/        market.js（商品/筛选/收藏/评论）、user.js（登录/主题）
├─ composables/   7 个组合式函数（防抖、本地存储、相对时间…）
├─ directives/    v-highlight、v-ripple
├─ plugins/       全局轻提示插件
├─ data/          28 条模拟商品 + 分类字典
├─ components/    layout 3 / common 7 / market 9 / home 3 / lab 12
└─ views/         8 个页面
```

一句话总结分层：**数据层（data）→ 状态层（stores）→ 复用层（composables / directives / plugins）→ 组件层 → 页面层**。

## 四、三个技术亮点（重点讲这三个，其余被问到再说）

1. **状态集中管理**：市场页的关键词、分类、价格、排序、页码全在 `stores/market.js`，
   子组件只负责「写入 store」和「渲染 store」，彼此不通信也能联动。
   `filteredItems` 用 computed 串起四个筛选条件，依赖不变时走缓存。
2. **一键流式复用机制**：同一个「收藏」动作，在卡片、详情页、收藏页三处都用 `market.toggleFavorite()`；
   同一个「相对时间」逻辑抽成 `useRelativeTime()`；关键词高亮抽成 `v-highlight` 指令；全局提示抽成插件。
3. **一处数据、两处 UI**：发布页的左侧表单和右侧预览共享同一个 `form` 对象，
   直观体现「数据驱动视图」；这也是 Vue 与「手动操作 DOM」最本质的区别。

## 五、高频提问与标准答案

1. **为什么用 Hash 路由（地址带 #）？**
   项目部署在 GitHub Pages 的子路径下，Hash 模式刷新页面不会打到服务端，不会 404，也不需要服务端重写规则。

2. **computed 和 methods / watch 有什么区别？**
   computed 是「派生数据」，有缓存，依赖不变就不重算（实验室里用「求值次数」直观验证过）；
   watch 是「数据变化后做一件事」（副作用），可以 deep、immediate，返回的函数还能停止侦听；
   methods 每次渲染都会执行，没有缓存。

3. **v-model 的本质是什么？**
   `v-model="x"` 就是 `:value="x"` + `@input="x = $event.target.value"` 的语法糖；
   在组件上则是 `:modelValue` + `@update:modelValue`，Vue 3.4 之后用 `defineModel()` 声明最简洁。

4. **v-for 为什么必须写 key？用 index 行不行？**
   key 让 Vue 能精确复用/移动节点。用 index 作 key，在删除中间项或排序时，DOM 会被错误复用
   （实验室「列表渲染」里删一条待办就能看到串行现象）。

5. **v-if 和 v-show 怎么选？**
   v-if 是真正的条件渲染（销毁/重建 DOM），适合切换少、初始可能不渲染的场景；
   v-show 只是切 `display:none`，切换开销小，适合频繁切换。

6. **props / emit / 插槽 / provide-inject 分别什么时候用？**
   props 向下传数据，emit 向上报事件，插槽让父组件决定子组件某块区域怎么渲染（作用域插槽还能把子组件的数据传回去），
   provide/inject 用于跨多层传参（如根组件 provide 站点信息，页脚和实验室直接 inject）。

7. **数据为什么刷新不丢？**
   Pinia 里的 `watch` 侦听收藏、已发布商品、评论，变化就写入 localStorage，初始化时读回来；
   读取用 try/catch 包住，防脏数据导致白屏。

8. **scoped 样式为什么对自定义指令生成的 `<mark>` 不生效？**
   scoped 是靠给元素加 `data-v-xxx` 属性实现的，运行时用 JS 创建的节点没有这个属性，
   所以要用深度选择器 `:deep(mark.ny-hl)`。

9. **异步组件和普通组件的区别？**
   异步组件（`defineAsyncComponent`）会单独打包，用到时才下载；它的 setup 里可以用顶层 await，
   但必须由 `<Suspense>` 包裹，等待期间显示 fallback（首页的平台动态、实验室的分类占比图都是这样）。

10. **为什么在 onUpdated 里写响应式数据会死循环？（我的踩坑经历）**
    onUpdated 在 DOM 更新后触发，我往被模板渲染的数组里 push 日志，又触发一次更新 → 无限递归，
    报 `Maximum call stack size exceeded`。解决办法是加「值是否真的变化」的判断，并把纯调试信息改成 console.log。

11. **组件销毁时要注意什么？**
    定时器、事件监听、手动创建的资源都要在 onUnmounted 里清理，否则内存泄漏；
    轮播 Banner 的 `setInterval` 就做了 clearInterval。

12. **这个项目性能上做了什么？**
    路由懒加载（按页面分包）、构建产物 gzip 后首页 65 kB；computed 缓存避免重复筛选；
    长列表只渲染当前页 8 条；搜索用防抖（customRef 实现）减少计算。

13. **如果数据量很大怎么办？**
    目前筛选和分页在客户端做，数据量大时应改为服务端分页 + 虚拟列表；图片也要走 CDN 与懒加载。

14. **有没有做测试？**
    写了 `tools/screenshot.mjs`，用 Playwright 自动走 20 个场景、保存 25 张截图，并断言控制台 0 错误 / 0 警告。

15. **怎么部署的？**
    `tools/deploy-gh.mjs`：创建仓库 → 推源码到 main → 以 `BASE_PATH=/仓库名/` 构建 → 把 dist 推到 gh-pages 分支 → 调 API 开启 Pages。

## 六、收尾（15 秒）

> 这次实验最大的收获不是记住了 API，而是理解了「数据驱动视图」这件事：
> 状态集中管理、组件各司其职、副作用收敛到明确时机。
> 不足是没有后端、图片是渐变占位，后续打算接入接口、补 TypeScript 和单元测试。
